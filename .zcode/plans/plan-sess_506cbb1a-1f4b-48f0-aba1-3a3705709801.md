# PR: Corregir las 9 alertas de Dependabot

Resuelve las 9 alertas abiertas (4 high, 4 medium, 1 low) con 3 cambios de dependencias + adaptaciones de código. Todo en un branch nuevo, con verificación de tests antes de abrir el PR.

## Alertas cubiertas
| # | Paquete | Severidad | Origen del fix |
|---|---|---|---|
| 1,3,5,6,7,8,9 | starlette | 4H/3M | subir FastAPI → Starlette 1.3.1 |
| 2 | ecdsa | high | migrar jose→pyjwt (elimina ecdsa) |
| 4 | pytest | medium | subir pytest a 9.0.3+ |

## Cambios

### 1. `pyproject.toml` — versiones
- `fastapi>=0.115.0,<0.116.0` → `fastapi>=0.137.0,<0.138.0`
- añadir pin explícito `starlette>=1.3.1,<2.0.0` (garantiza el parche)
- `python-jose[cryptography]>=3.3.0,<4.0.0` → `pyjwt>=2.10.0,<3.0.0` (sin extra `[crypto]`, HS256 no lo necesita)
- `pytest>=8.3.4,<9.0.0` → `pytest>=9.0.3,<10.0.0`
- `pytest-asyncio>=0.25.0,<0.26.0` → `>=0.26.0,<0.27.0` (compatible con pytest 9)
- añadir `asyncio_default_fixture_loop_scope = "session"` a `[tool.pytest.ini_options]` (requerido por pytest-asyncio 0.26)

### 2. Migración jose → pyjwt (5 archivos)
API 1:1 para HS256. Solo cambia el import y el nombre de la excepción (`JWTError` → `PyJWTError`):
- `src/gad/auth/jwt.py`: `from jose import JWTError, jwt` → `import jwt` + `from jwt import PyJWTError`; renombrar los 2 `JWTError` → `PyJWTError`
- `src/gad/safety/tokens.py`: mismo cambio; renombrar 2 `JWTError` → `PyJWTError`
- `src/gad/safety/service.py:210`: `from jose import jwt as jose_jwt` → `import jwt`; `jose_jwt.decode` → `jwt.decode` (el bloque ya captura `Exception`, sin cambio)
- `tests/test_jwt.py`: `from jose import JWTError` → `from jwt import PyJWTError`; `pytest.raises(JWTError)` ×2 → `PyJWTError`
- `tests/test_safety_tokens.py`: mismo cambio; `pytest.raises(JWTError)` ×2 → `PyJWTError`

### 3. slowapi — validar tras el bump (riesgo nº1)
slowapi 0.1.10 puede ser incompatible con Starlette moderno (handler `_rate_limit_exceeded_handler`). No se cambia preemptivamente: tras el `uv lock`, correr los tests de rate-limit. Si rompe:
- (a) probar bump de slowapi fuera del rango actual (es dev-mantained, posible fix upstream), o
- (b) workaround: handler propio con la firma nueva de Starlette en `rate_limit.py`.
Se decide según lo que diga la suite, no a ciegas.

### 4. `uv.lock` — regenerar
`uv lock` tras editar `pyproject.toml`. Verificar que queden `starlette 1.3.x`, `fastapi 0.137.x`, `pyjwt` y **sin `ecdsa`** en el lock.
